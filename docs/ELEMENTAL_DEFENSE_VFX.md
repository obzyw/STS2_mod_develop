# 两张防御牌特效：开发与验证

## 2026-10-26 下午：动作丢甲与火墙退场修复

用户实测指出铁甲战士举盾等非待机动作丢甲，以及火墙退场过快。本轮确认了三个相关遗漏：只在首次覆甲时绑定非空附件；盾牌 Mod 隐藏原 SpineMesh2D 却保留骨架节点，旧查找仍选中隐藏本体；其片元 Shader 使用默认 COLOR，旧采样替换不足以覆甲。新增连续帧夹具又在耸肩无视切换动作人物时捕获一帧未覆甲，已将绑定更新移到 frame_pre_draw。

| 修改 | 内容 |
|---|---|
| 身体选择 | 检查实际可见 SpineMesh2D，继续寻找嵌套/兄弟动作人物；保留已有前景 DisplayLease 适配 |
| 附件覆盖 | 提前绑定有身体名称的空槽，持续发现新附件和网格，幂等添加，避免重复叠层 |
| 材质 | 保留作者完整片元处理及 alpha，再混合岩石颜色；原 uniform 动画继续同步 |
| 绘制时序 | 绘制前解析最终显示人物，处理其他 Mod 在 _process 之后进行的身体接管，消除已捕获的一帧空窗 |
| 火墙退场 | 用真实时钟推进约0.65秒平滑淡出，不被5倍游戏时间压成瞬间 |

检查范围为本机启用配置，不声称穷尽所有工坊动作。死亡导致能力失效、战斗场景销毁与正常能力移除不属于“仍有覆甲却闪回原材质”的判定范围。

这是上述环境的开发验证，不是所有角色/皮肤/Mod 任意组合的认证，也不是美术验收。共享的选牌与反伤代码在六角色批次验证，冻结替身和数字皮肤分别按受影响范围补测，没有重跑旧四组兼容验证。

原生岩石铠甲数值由游戏和现有 Mod 决定。当前环境中第三方可能把覆盖层改成3，夹具读取实际卡牌 DynamicVars，不强行断言原版4；本模块不修改战斗数值。

多 Mod 环境正常退出仍报告引擎资源未释放警告；退出码0不等于证明没有资源问题。没有进行多人联机、所有皮肤、所有程序化 Shader 的穷尽验证。

# 2026-10-26：火墙盖住暂停/退出菜单

用户反馈火墙出现在右上角退出菜单前方。独立特效根节点原先继承角色外观的 Z，火墙等子节点还有正 Z，反弹根节点另外加了20；同一画布内的 Z 会越过场景树中的 UI 顺序。现将特效根节点设为不继承 Z，跟随游戏 CombatVfxContainer 当前深度，独立环绕/火墙子节点不再额外抬高，反弹也归还原生容器深度。身体岩甲仍使用原网格，不改原作者人物层级。

必要验证使用新的 `-UiLayerAudit` 分支，只测试本次层级变更：实际出牌形成火墙，通过右上角暂停按钮入口打开原生菜单，在火墙位置放置菜单内不透明测试控件并读回 GPU 像素，确认菜单覆盖；关闭菜单后火墙仍存在。另把夹具中的角色层级临时提高到100，确认特效不跟随。没有点击“放弃”或“保存并退出”，不操作原存档。最终批次结果见精选证据。
